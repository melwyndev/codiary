# Project Constitution: Codiary

> **Framework:** Spec-Driven Development (SDD)  
> **Reference:** JetBrains & DeepLearning.AI Spec-Driven Engineering Standards  
> **Status:** Active & Enforced  

---

## 1. Philosophical Foundations & Core Tenets

1. **Specification Precedes Implementation**: Code is an ephemeral downstream artifact generated from explicit specifications. We do not write ad-hoc code or rely on "vibe coding" prompts. The specification defines the **WHAT** and **WHY**; the agentic implementation implements the **HOW**.
2. **Zero Context Decay**: Agents and developers operate across multi-turn sessions with stateless boundaries. Non-negotiable technical constraints, design systems, and data models must live in durable repository specifications to prevent drift and regressions.
3. **Intent Fidelity & Human-Agent Contract**: Specifications declare domain problems, boundary constraints, role models, and acceptance criteria. Code generated by coding agents must strictly adhere to this contract without introducing unauthorized dependencies or unintended architectural paradigms.
4. **Local-First Speed with Cloud Authority**: The user interface must feel instantaneous (<16ms frame-0 feedback) with optimistic state updates, while PostgreSQL and PostgREST via InsForge BaaS serve as the authoritative single source of truth.

## 3. Architecture & Security Invariants

### 3.1 Authentication & Multi-Tenancy
- Authentication is managed via InsForge Auth (`auth.users`).
- Notes are strictly partitioned by `user_id` and `owner_email`.
- No anonymous or public writes: all write mutations require an authenticated session or explicit role delegation.

### 3.2 Access Control & Role Matrix (Sharing Engine)
Access to notes is governed by a declarative permission matrix stored in PostgreSQL table `note_shares`:

| Role | Read Canvas | Edit Blocks | Rename Document | Manage Tags & Icons | Delete Note | Manage Sharing |
| :--- | :---: | :---: | :---: | :---: | :---: | :---: |
| **Owner** | ✅ | ✅ | ✅ | ✅ | ✅ | ✅ |
| **Editor** | ✅ | ✅ | ❌ | ❌ | ❌ | ❌ |
| **Viewer** | ✅ | ❌ | ❌ | ❌ | ❌ | ❌ |

- **Viewer Enforcements**: The editor canvas is mounted in read-only mode, block add/edit buttons are hidden, slash commands are disabled, and headers reflect a `Viewer (Read Only)` badge.
- **Editor Enforcements**: Collaborator can modify block content, code snippets, and checklists, but cannot delete or alter document ownership.

### 3.3 File Ingestion Invariants
- Direct document imports (`.md`, `.txt`, `.json`) are parsed **client-side in the browser** without transmitting raw files to intermediary compute servers.
- **Size Boundary**: Hard cap at **10 MB** enforced via pre-upload client validation.
- **Type Guard**: Strict extension whitelisting (`.md`, `.txt`, `.json`). Unsupported MIME types are rejected with immediate user-facing alerts.

### 3.4 Export Invariants
- Dual export capabilities must be accessible both from the workspace library (`/notes` context menu) and the active canvas (`Export ▾` dropdown).
- **Markdown Export**: Must export clean markdown with YAML metadata frontmatter (`title`, `tags`, `updatedAt`).
- **PDF Export**: Must invoke a dedicated CSS print-sheet (`@media print`) that strips UI navigation, sidebars, and control buttons to generate a presentation-ready document.

## 4. Engineering Quality Standards

1. **Strict TypeScript**: No implicit `any` in core stores or API routes (`npx tsc --noEmit` must pass with 0 errors).
2. **Visual Feedback on All Operations**: Every asynchronous mutation (save, import, share, rename, delete) must provide immediate toast feedback and visual progress indicators.
3. **Resilience & Graceful Fallbacks**: Network disconnections or backend cold-starts must fall back to local in-memory storage without crashing or data loss.
